# 14 | 闪卡复习页与动态卡宿主设计

> 2026-09-27 起草。前置：郭老师拍板「新增『闪卡复习』二级页面，一级页（课程首页）加图标；生词本页内快捷入口保留（两处都留）」。
> 关联：08_核心精听优先_产品优先级定调、10_生词本与Anki记忆卡设计。

## 一、概念澄清（定名纪律）

- **App 内闪卡 ≠ Anki**：Anki 只是导出格式（.apkg 快照，见 10 号文档 §24）。App 内复习走自有 FSRS 调度 + 生词本数据。
- 页面命名：**「闪卡复习」**（不叫 Anki 页），避免用户误以为必须安装 Anki 才能用。

## 二、架构红线核对

| 红线 | 本设计 |
|---|---|
| 附属功能只走二级入口 | ✅ 闪卡复习 = 二级页面 |
| 不做底部 tab 增位 | ✅ 一级页加图标，不碰底部导航 |
| 附属功能不阻塞核心链路 | ✅ 复习数据全本地（FSRS），零 AI 依赖，天然满足降级原则 |

## 三、导航结构

```
一级页（课程首页）
├─ 生词本卡片 ────────→ 生词本页（保留快捷入口「闪卡复习 · N 张到期」）
└─ 闪卡复习卡片（新增）→ 闪卡复习页（本设计）
```

- 首页现有生词本卡片改为**双卡并排**（生词本 | 闪卡复习）。
- 复习卡徽标：`今日到期 N 张`；N=0 时弱态显示「今日复习已完成」。
- **两处都留**（郭老师拍板）：生词本页内保留快捷入口——复习有两条自然路径（背词时顺手复习 / 每日固定复习）。
- 底部导航不增位（红线）。

## 四、页面结构（V1）

1. **到期队列概览**：今日到期 N 张（FSRS due ≤ now）、已完成 X/N、连续天数（可后续加）。
2. **复习卡交互**：复用现有 `VocabularyReviewScreen` 评分逻辑——Again / Hard / Good / Easy → `fsrs` 包 `Scheduler.reviewCard()`；评分后立即写回 `VocabularySrs`。
3. **完成态**：本轮完成 X 张 + 下次到期分布提示。
4. **空态**：无到期卡时显示「今日复习已完成 ✅」+ 明日预告（不新增卡，不越权调度）。

### 硬边界（延续生词本三条硬边界）

1. 复习页只消费 FSRS 到期队列，**不改变队列构成**（新卡入场仍只由听写错误/收藏驱动）。
2. 不碰原声句轴与听写判定（核心链路零依赖）。
3. AI 故障时降级为纯静态卡，复习流程不断（为动态卡预留的降级红线）。

## 五、与动态卡的衔接（本页 = Interaction 宿主）

按 GPT 评审采纳的五层架构（10 号文档 §二十四引用）：

```
MemoryItem（FSRS 唯一调度对象）
   → Policy Engine（确定性规则选交互类型 + cue level）
      → Content Components（AI 生成 schema JSON / 静态模板兜底）
         → Native Renderer（本页面渲染）
```

- V1：本页只渲染静态闪卡（正面/背面 + 评分）。
- 动态卡落地后：同一页面按 Policy Engine 输出渲染 **语境填空 / 易混词对比 / 助记口诀 / 听辨卡** 等组件，页面骨架不变。
- 生词本页快捷入口与一级页入口指向**同一个复习页**，队列同一份（FSRS 到期队列唯一真源）。

## 六、实现清单（V1，一个迭代）

1. 路由 + 入口（首页双卡）+ 页面壳（复用 review 逻辑）
2. l10n 双语文案
3. 测试：到期队列构成（FSRS 到期驱动）、评分写 FSRS 状态、零到期空态、入口路由
