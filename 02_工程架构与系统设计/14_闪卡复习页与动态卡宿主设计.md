# 14 | 闪卡复习页与动态卡宿主设计

> 2026-09-27 起草。前置：郭老师拍板「新增『闪卡复习』二级页面，一级页（课程首页）加图标；生词本页内快捷入口保留（两处都留）」。
> 关联：08_核心精听优先_产品优先级定调、10_生词本与Anki记忆卡设计。

## 一、概念澄清（定名纪律）

- **App 内闪卡 ≠ Anki**：Anki 只是导出格式（.apkg 快照，见 10 号文档 §24）。App 内复习走自有 FSRS 调度 + 生词本数据。
- 页面命名：**「闪卡复习」**（不叫 Anki 页），避免用户误以为必须安装 Anki 才能用。

## 二、架构红线核对

| 红线 | 本设计 |
|---|---|
| 附属功能只走二级入口 | ✅ 闪卡复习 = 二级页面 |
| 不做底部 tab 增位 | ✅ 一级页加图标，不碰底部导航 |
| 附属功能不阻塞核心链路 | ✅ 复习数据全本地（FSRS），零 AI 依赖，天然满足降级原则 |

## 三、导航结构

```
一级页（课程首页）
├─ 生词本卡片 ────────→ 生词本页（保留快捷入口「闪卡复习 · N 张到期」）
└─ 闪卡复习卡片（新增）→ 闪卡复习页（本设计）
```

- 首页现有生词本卡片改为**双卡并排**（生词本 | 闪卡复习）。
- 复习卡徽标：`今日到期 N 张`；N=0 时弱态显示「今日复习已完成」。
- **两处都留**（郭老师拍板）：生词本页内保留快捷入口——复习有两条自然路径（背词时顺手复习 / 每日固定复习）。
- 底部导航不增位（红线）。

## 四、页面结构（V1）

1. **到期队列概览**：今日到期 N 张（FSRS due ≤ now）、已完成 X/N、连续天数（可后续加）。
2. **复习卡交互**：复用现有 `VocabularyReviewScreen` 评分逻辑——Again / Hard / Good / Easy → `fsrs` 包 `Scheduler.reviewCard()`；评分后立即写回 `VocabularySrs`。
3. **完成态**：本轮完成 X 张 + 下次到期分布提示。
4. **空态**：无到期卡时显示「今日复习已完成 ✅」+ 明日预告（不新增卡，不越权调度）。

### 硬边界（延续生词本三条硬边界）

1. 复习页只消费 FSRS 到期队列，**不改变队列构成**（新卡入场仍只由听写错误/收藏驱动）。
2. 不碰原声句轴与听写判定（核心链路零依赖）。
3. AI 故障时降级为纯静态卡，复习流程不断（为动态卡预留的降级红线）。

## 五、与动态卡的衔接（本页 = Interaction 宿主）

按 GPT 评审采纳的五层架构（10 号文档 §二十四引用）：

```
MemoryItem（FSRS 唯一调度对象）
   → Policy Engine（确定性规则选交互类型 + cue level）
      → Content Components（AI 生成 schema JSON / 静态模板兜底）
         → Native Renderer（本页面渲染）
```

- V1：本页只渲染静态闪卡（正面/背面 + 评分）。
- 动态卡落地后：同一页面按 Policy Engine 输出渲染 **语境填空 / 易混词对比 / 助记口诀 / 听辨卡** 等组件，页面骨架不变。
- 生词本页快捷入口与一级页入口指向**同一个复习页**，队列同一份（FSRS 到期队列唯一真源）。

## 八、GPT Extended 评审结论采纳（R4，2026-09-28）

评审原文：`03_研发日志与历史归档/GPT评审_闪卡复习页_2026-09-28/GPT评审_R4_闪卡复习页与动态卡宿主.md`。核心采纳（8 条）：

1. **命名与抽象分层**：用户侧叫「每日到期复习」，工程侧实现为通用 **Review Session Host**——不要把页面演化成训练中心，也不要绑死 StaticFlashcard。
2. **一条路由 + 四态**：只用一条 `ReviewSessionRoute`，内部 `ReviewSessionHost` 覆盖 Loading/Reviewing/Completed/Empty 四态；内部类名 `ReviewSessionScreen/Controller/State`（不叫 StaticFlashcardReviewScreen）。
3. **首页双卡降级为「词汇记忆」紧凑二级区块**：与「继续精听」核心 CTA 保持视觉权重差；徽标文案用「**待复习 N 张**」（due ≤ now 含逾期项，「今日到期」语义不准）。
4. **双入口零语义差异**：两个入口进同一个 `ReviewSessionRoute()`，`source` 仅用于埋点（enum ReviewEntrySource { home, vocabulary }），队列/排序/Policy/FSRS/组件/完成逻辑全部一致。
5. **队列 = Session Snapshot**：打开复习页时按 `sessionStart` 时刻的 due 固定快照，`initialCount` 固定，评分用 `ratedAt`——避免复习过程中队列漂移。
6. **组件模型**：`sealed class ReviewComponentModel`（StaticFlashcardModel / ContextClozeModel / …）；AI schema 变化只改 JSON adapter，Renderer 不动。
7. **Content Resolver 永不等 AI**：`resolveNow()` 同步返回（有缓存用动态组件，无缓存立即返回 StaticFlashcardModel，绝不发网络等待）；`prefetch()` 对后续 3–5 张预取。当前卡 100% 本地打开。
8. **Renderer 用 Registry** + **组件结果与 FSRS 评分解耦**：组件返回 `InteractionResult`（completed/correct/usedHint/responseTime），FSRS 只接 Rating；V1 由用户手动评分，未来自动评分走 RatingPolicy 中转。**Policy Decision 在 item 进入 session 时固定一次**（记录 policyVersion/ruleId/cueLevel，可复现）。

### V1 实现清单（按评审修订，8 项）

1. 首页词汇记忆双卡 + 生词本快捷入口 → 同一 `ReviewSessionRoute`
2. Review Session：startedAt / due≤startedAt 快照 / initialCount 固定 / rating 用 ratedAt
3. `ReviewSessionHost`：Reviewing / Completed / Empty 三态（不绑卡型）
4. Policy Engine V1：InteractionType / CueLevel / InteractionPlan / 永远返回 staticFlashcard
5. Content：StaticFlashcardModel + ReviewContentResolver + 本地同步 fallback
6. Renderer：RendererRegistry + StaticFlashcardRenderer
7. Scheduling：renderer 不写 FSRS，session controller 统一 reviewCard()
8. 测试：队列快照不漂移 / 两入口同队列 / Policy 确定性 / fallback 永远可用 / rating 写回同一 MemoryItem

> GPT 总结原则：**「闪卡复习」是产品名称；ReviewSessionHost 才是工程抽象。任何由 FSRS 到期 MemoryItem 驱动的交互都可以进宿主，任何独立训练都不要进。**
