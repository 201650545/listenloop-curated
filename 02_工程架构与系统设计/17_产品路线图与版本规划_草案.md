# 17 · 产品路线图与版本规划（草案 · 送审版）

> 定位：ListenLoop 以 APP 为载体，**AI 生成各种交互设计**，提升体验与学习效率，实现有效学习。
> 本文由 Agent（金小满）起草，送 ChatGPT（Thinking•Extended）评审后定稿。
> 关系文档：08 优先级定调 / 09 听写引擎 / 15 产品北极星 / 16 听写完成流（含 turn3 评审结论）

## 一、长远目标（12 个月视野）：听力驱动的语言习得系统

**北极星不变**（15 号）：从「精听工具」升级为「听力驱动的语言习得系统」。

**AI 生成交互（用户的原话「AI 生成各种交互设计」）分三步走**，对应 15 号三阶段：

| 阶段 | AI 的角色 | 用户可感知 |
|---|---|---|
| Phase A（现在-1.5 月）| AI 做反馈者：governor 给结构化反馈 | 错句→产出→反馈的闭环 |
| Phase B（1.5-4 月）| **AI 做设计者**：给定 primitives + interaction graph + evaluator，AI 组合出新的练习交互 | 同一课，AI 按你的薄弱点生成不同练习形态 |
| Phase C（4-12 月）| AI 做课程架构师：KnowledgeGraph × LanguageGraph × LearnerModel | 「用英语学进化论」而非「用进化论学英语」 |

**判据**：Phase B 的启动前提（15 号）是 Phase A 的交互类型足够多，才能验证 primitives 边界。所以节奏上 **Phase A 不能跳**，但可以压缩。

## 二、中期目标（4 周）：Phase A 完成 + Phase B 首个 primitives 打样

| 周 | 交付 | 对应缺口 |
|---|---|---|
| W1（本周）| 完成流双出口（ProductionTarget + ListenRetryTarget）+ 入口优化 + AI 反馈清洗 | turn3 评审三刀 |
| W2 | **Parsing Challenge α**（缺口二：自动化/timed processing；复用 FSRS 队列+课程语料，工程量小） | 缺口二 |
| W3 | Parsing Challenge 打磨 + Micro Grammar α（错误模式→语法点映射先做听写错句的 top3 模式） | 缺口一 |
| W4 | **Phase B 打样**：把「填空/排序/选择」抽象成 3 个 primitives，让 AI 按错句证据组合生成一个小练习 —— 验证 interaction graph 可行性 | Phase B 前置验证 |

**中期验收**：四种交互类型（Meaning Recall / Parsing / Chunk Composer 缓 / Micro Grammar）中完成三种，且 Phase B 打样能跑通一个 AI 生成的练习。

> Chunk Composer 明确后置（需语料标注，工程量大，15 号已定）。

## 三、短期目标（今晚-明天，v0.9.1 直接可体验）

**今晚实现、明早可装的三件套**（全部来自 turn3 评审、低成本高感知）：

1. **入口位置修正**：「N 句有待打磨」入口从「重写本段/下一段」下方移到 **diff 结果区末尾、主导航之前**——避免被主 CTA 吞掉漏斗。
2. **双出口完成流**：批改页出现两个语义化区域——
   - 「N 句需要你自己说出来 → 去意思回忆」（ProductionTarget: errorCount>0 && !uncertain && !isBlank）
   - 「M 句还没听清 → 回原声重听」（ListenRetryTarget: isBlank || uncertain，定位到句首回听）
   - 解决 turn3 指出的逻辑缺口：uncertain 句此前没有专属完成流出口。
3. **AI 反馈清洗**：governor 返回的 Markdown 记号（#/##/**）做轻量清洗渲染（不做完整 renderer，控范围）——turn3 规格 7。

## 四、版本序列（大小版本节奏）

| 版本 | 内容 | 性质 |
|---|---|---|
| **v0.9.1**（今晚）| 完成流双出口 + 入口优化 + AI 反馈清洗 | 小版本·可体验 |
| v0.9.2 | Parsing Challenge α（选择题式句法拆解，倒计时） | 小版本 |
| v0.9.3 | Micro Grammar α（听写错句 top3 模式→语法点） | 小版本 |
| **V1.0**（≈4 周后）| Phase A 三交互闭环 + 数据红线 + 降级完备 | **大版本**：精听工具→习得系统 |
| V1.1 | Phase B primitives 验证版（AI 生成练习）| 大版本预览 |

**大版本判据**（V1.0 gate）：① 三种交互全走 governor 且可降级；② 听写→复习→产出全链路数据留痕；③ 真机端到端复验通过。

## 五、边界（不做清单，沿用 08/15 号）

- ❌ 不做 TTS / 语音合成（15 号 Phase A 不做）
- ❌ 不做完整 Markdown renderer（轻量清洗即可）
- ❌ 不做 Chunk Composer（W4 前不碰）
- ❌ 不推翻五层架构（Phase A 新交互 = Content Components 新组件）

## 送审问题（3 条）

1. **节奏判断**：Phase A 三交互（W2-W3）+ Phase B 打样（W4）的四周压缩节奏是否可行？最大的风险是什么？
2. **Phase B 打样的 primitives 选型**：首批 3 个 primitives 选「填空 / 排序 / 选择」是否正确？有没有更该先验证的 primitive？
3. **v0.9.1 三件套之外**，有没有遗漏的「明天就能感受到」的体验修补？（例如视频模式刚修的 Error 153 是否需要加重试提示？）
