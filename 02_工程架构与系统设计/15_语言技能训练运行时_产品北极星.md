# 15 ｜语言技能训练运行时：ListenLoop 产品北极星

> 2026-09-28 起草。基于 GPT Extended R5 战略评审（19147 字，见 03_归档/GPT评审_战略愿景_2026-09-28/）核心采纳结论。
> 关联：08_核心精听优先_产品优先级定调、10_生词本与Anki记忆卡设计、14_闪卡复习页与动态卡宿主设计。

## 一、定位升级（产品北极星）

**旧定位**：英语精听工具。

**新定位**：语言技能训练运行时（Learning Runtime）——AI 决定此刻要制造什么学习经历，App 提供安全、确定、可离线执行的交互原语。

> 精听只是这个 runtime 的第一个 application。用英语学历史、科学、哲学会成为第二个 application。

**长线愿景**：App 是白板/载体，AI 附身于载体实时创作学习交互形态；当前聚焦英语单点，长期用英语学系统性知识。

## 二、科学性审计（Nation Four Strands）

| 能力维度 | ListenLoop 现状 | 评估 |
|---|---|---|
| Meaning-focused input | 精听、原声 | 有但偏 intensive，需泛听梯度 |
| Language-focused learning | 听写、diff、生词、FSRS | **强项** |
| Meaning-focused output | 几乎没有 | **最大缺口 ★★★★★** |
| Fluency development | 几乎没有 | **第二缺口 ★★★★** |

### 两个理论纠偏

1. **逐句精听 ≠ 大量可理解输入**：精听是 intensive listening / form-focused decoding，适合解决连读/弱读/词边界问题，但「大量」需要泛听补充。未来形成**精听→半精听→泛听**梯度。
2. **听写 ≠ Swain 输出假设**：听写是 audio → representation → orthography（听力诊断器 + noticing machinery），真正的 productive output 是 meaning → language（方向相反）。听写很好但不是完整输出训练。

## 三、三大缺口（优先级排序）

### 缺口一：主动表达 / pushed output ★★★★★

最简形态（无需语音）：听完 → 隐藏原文 → **用英语表达刚才的意思**（不要求原句）→ AI 反馈（意思表达成功/缺 article/搭配问题/更自然版本）→ 修正输出。

形成循环：理解 → 输出 → gap → feedback → modified output。

### 缺口二：流利度 / 自动化 ★★★★

「知道 despite = 尽管」和「300ms 内听懂 despite the fact that」是不同能力。需增加 **timed processing** 训练（限时选择题等）。关键原则：**FSRS 管知识保持，Policy Engine 管处理流畅度**——两者是独立维度。

### 缺口三：语音感知 ★★★

diff 能告诉用户「你把 can 听成了 can't」，但真正需要学的是**为什么**：vowel / weak form / assimilation / linking / lexical segmentation / stress。HVPT（高变异语音训练）有研究基础。

## 四、AI 白板：正确技术路线

**不做**：LLM 写任意代码 / WebView 执行任意 HTML。
**要做**：LLM 编排有边界的 **Learning DSL**。

现有架构不推翻，进化为：

```
Learner Model（语言模型 + 知识模型 + 流利度模型）
   → Policy Engine（为什么练：缺口驱动）
      → AI Composer（怎么呈现：生成 Learning DSL 实例）
         → Artifact IR（中间表示：有边界的交互描述）
            → Native Runtime（Flutter 渲染）
```

**AI artifact 五问纪律**（每个 artifact 进 UI 前必须回答）：

```yaml
learning_target: lexical_segmentation
failure_model: "hears 'a nice cold hour' instead of 'an ice-cold shower'"
desired_cognitive_operation: boundary_discrimination
evidence_of_learning: correct segmentation without transcript
transfer_target: unseen connected-speech samples
```

## 五、三阶段路线图

### Phase A：完成语言闭环

补齐四个新交互类型（每个都映射一个科学缺口）：

| 新交互 | 填补缺口 | SLA 依据 |
|---|---|---|
| Meaning Recall | 缺口一 | Swain pushed output + corrective feedback |
| Parsing Challenge | 缺口二 | Automaticity / timed processing |
| Chunk Composer | 缺口一 | Formulaic sequences / lexical approach |
| Micro Grammar | 缺口一 | Focus on form / metalinguistic feedback |

完成后 ListenLoop 从「精听工具」升级为「听力驱动语言习得系统」。

### Phase B：Generative Learning Runtime

把练习类型抽象成 primitives + interaction graph + evaluator，AI 开始组合 UI——这是「AI 白板」的真正落地。前提：Phase A 的交互类型足够多，才能验证 primitives 的边界设计是否正确。

### Phase C：Language-through-Knowledge

加入 KnowledgeGraph + LanguageGraph + LearnerModel 双模型。课程变成 `Learn Evolution in English` 而非 `Learn English using a video about Evolution`。AI 白板在这个阶段才真正打开：系统不仅知道用户哪个英语词不会，还知道哪个知识概念没建立起来。

## 六、内容源四层策略（TED-Ed 授权风险应对）

| 层 | 说明 | 价值 |
|---|---|---|
| A. Licensed premium | 正式授权的高质量内容 | 高质量真实英语 |
| B. Open-licensed | 开放教育资源（允许衍生） | 可重组/生成练习/知识图 |
| C. ListenLoop Original | 请真人录制，自有全部权利 | **长期 moat** |
| D. Bring Your Own Content | 用户导入 podcast/lecture/article | 白板愿景完全打开 |

**TED-Ed 现状**：BY-NC-ND 授权限制商用与衍生，且限制 AI/ML workflow 使用。短期验证可用，**长期 corpus moat 不能建立在无法自由衍生的第三方内容上**。

## 七、Phase A 首批实现优先级

| 优先 | 交互 | 依赖 | 工程量 |
|---|---|---|---|
| 1 | Meaning Recall | 听写引擎复用 diff，AI 反馈走 governor | 中 |
| 2 | Parsing Challenge | 复用 FSRS 队列 + 课程语料 | 小 |
| 3 | Chunk Composer | 需语料标注（chunk 边界） | 大 |
| 4 | Micro Grammar | 需错误模式 → 语法点映射 | 中 |

## 八、与现有架构的关系

- 现有五层（MemoryItem → Policy → Components → Renderer）**不推翻**，是本设计 Phase A 的骨架。
- Phase A 新增的四种交互类型 = Content Components 层的新组件类型（与静态闪卡并列）。
- Phase B 的 Learning DSL = Content Components 层的 schema 演进（从固定 schema 到可组合 primitives）。
- Phase C 的 KnowledgeNode = MemoryItem 的上层对象（一个 KnowledgeNode 关联多个 Language MemoryItem）。

## 九、不做清单

- ❌ 不做通用 AI 聊天界面
- ❌ 不做 WebView 内嵌任意 HTML 交互
- ❌ 不在 Phase A 做语音合成 / TTS
- ❌ 不在 Phase A 做知识图谱（Phase C 才做）
- ❌ 不为了「酷」而生成没有 learning_target 的交互
