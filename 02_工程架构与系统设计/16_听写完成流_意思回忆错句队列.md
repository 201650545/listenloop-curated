## 一、为什么现在做它

09 号听写引擎交付后，`DictationSegmentResult.reviewTargets` 已经能产出「有错误且对齐可靠」的句子，但**这条产出的下游是空的**：它只停留在页面上被看一眼，没有进入任何训练动作。

而 15 号文档 Phase A 里，Meaning Recall 被列为**优先级 1**，科学依据是 Swain 的 pushed output + corrective feedback（缺口一），并明确写出它的依赖是「听写引擎复用 diff，AI 反馈走 governor」。

本次交付就是把这两端接上：**听写批改出的错句 → 直接进入 Meaning Recall 队列**，让「漏了哪几个词」这个诊断结果立刻变成「你能不能把它说对」的训练动作。这一步把 09 从"诊断器"升级为"诊断 + 产出"闭环的一环。

### 它填的是哪一步

四步法：**盲听 → 听写 → 查证 → 背诵**。听写产出诊断（漏了哪几个词）；Meaning Recall 是**反向产出**——给中文释义，让用户用英语把意思说出来，AI 对比原句给结构化反馈。

两者正好互补：
- 听写 = audio → orthography（听力诊断器，考"能不能听清"）
- Meaning Recall = meaning → language（真正的 productive output，考"能不能说对"）

## 二、入口定位：常驻次级入口，不拦截不弹窗

### 交互契约

| 维度 | 设计 |
|:--|:--|
| 出现时机 | 批改阶段（`reviewing`），出现在「重写本段 / 下一段」按钮**下方** |
| 触发方式 | 页面常驻展示，**不自动弹出**、不截断用户看 diff |
| 文案 | `N 句有待打磨 → 去意思回忆`（`LLStrings.mrDrillEntry(count)`） |
| 隐藏条件 | 无合格错句时整块不渲染 |
| Key | `dictation-drill-entry`（供测试与自动化定位） |

### 为什么不做成自动跳转

听写批改后的核心动作是**看 diff、回原声重听**。如果提交完立刻弹 Meaning Recall，等于打断用户看自己错在哪——这违背 08 号「附属功能不得阻塞核心链路」的红线。所以入口**常驻但安静**：用户看完 diff 想练产出时自己点，不想练就继续下一段。

## 三、数据红线：什么句子进队列

`_drillSentences()` 的过滤规则，全部对齐 09 号听写引擎的批改契约：

```
line.uncertain  == true  → 排除（对齐不可靠，不伪造逐词诊断）
line.isBlank    == true  → 排除（留空是合法答案「没听出来」，不是错）
line.errorCount == 0     → 排除（完全正确，无需打磨）
```

三条都过 → 进入队列，**按句去重、按课内顺序**排列。

### 三条红线各自的理由

| 红线 | 理由 | 违反的后果 |
|:--|:--|:--|
| **uncertain 不进** | 09 号引擎在错误率 > 60% 时**诚实降级**，逐词对齐已无解释力 | 把不确定的东西当确定结论喂给 AI 反馈，放大幻觉 |
| **留空句不进** | 09 号明确「留空 ≠ 写错」，是用户诚实地表示没听出来 | 把"没听清"当成"不会表达"，训练目的错位 |
| **按句去重** | 用户可能反复重写某段；同句多段错误只练一次 | 同一句堆叠多份队列，稀释训练价值 |

### 边界情况

- **反复重写本段**：`completedSegmentResults` 只保留最新结果，重写会覆盖旧结果，队列不会堆积
- **全部留空**：队列为空，入口整块隐藏（用户选择诚实留空，尊重之）
- **全部写错导致 uncertain**：同样队列为空——这**符合设计**，错太多时先回原声重听，别急着产出

## 四、队列页：MeaningRecallDrillScreen

### 结构

```
AppBar: 错句练习
Body:
  ├─ 计数 + 说明（`第 N / M 句` + 数据红线提示）
  ├─ 中文释义卡片（原句隐藏）
  ├─ 输入框（maxLines 3）
  ├─ 提交按钮
  ├─ AI 反馈卡片（成功时）
  └─ 静态自比卡片（AI 不可用/失败时，显示原句）
Footer:
  ├─ 上一句 | 下一句 | 完成练习
```

### 用户操作序列

1. 听写批改页脚出现「N 句有待打磨 → 去意思回忆」
2. 点击 → 进入队列页，定位到第一句
3. 看中文释义 → 用英语表达意思 → 提交
4. 得到 AI 结构化反馈（yes/partially/no + 改进建议 + 更自然版本）
5. 点「下一句」继续，或「完成练习」返回听写
6. 任意时刻可返回上一句重练

### 状态机

- **未提交**：只显示中文释义与输入框
- **提交中**：按钮转 loading，防重复提交
- **AI 成功**：显示 AI 反馈卡片
- **AI 失败 / 无 governor**：显示原句静态自比（兜底，不断流程）
- **切换句子**：清空输入、清空反馈、重置状态

## 五、AI 降级策略（架构红线）

对齐 08 号「AI/TTS/ASR 故障一律降级」的红线：

| 场景 | 行为 |
|:--|:--|
| governor 为 null（未注入） | 整页走静态自比，**提交后直接显示原句** |
| `sendOnlineChat` 抛异常 | `_aiFailed = true` → 显示原句静态自比 |
| 加载超时 | 按钮 loading 直到超时返回；异常后走静态自比 |
| 输入为空 | 提交按钮直接 return，不发请求 |

**关键原则：AI 反馈是增强项，不是依赖项。** 复习流程在任何情况下都不应被 AI 故障阻塞。

### AI Prompt 设计

```
原句：<english>
用户的表达：<expr>

请对比用户的表达与原句，给出结构化反馈：
1. 意思是否表达到位（yes/partially/no）
2. 具体语法或词汇改进建议
3. 一个更自然的版本
用中文回答，简洁。
```

## 六、Governor 注入链路

```
LibraryScreen 持有 AiGovernorService
        │
        ├─→ VocabularyBookScreen → _VocabularyRow → MeaningRecallScreen（23ee9a5）
        │
        └─→ ListeningScreen.aiGovernorService → DictationScreen.governor（25e3548）
                                                          │
                                                          └─→ MeaningRecallDrillScreen
```

`DictationScreen` 的 `governor` 是**可选参数**：未注入时主流程零影响，只有入口按红线静默降级。这是为了让听写页在测试与独立使用时不被 AI 依赖。

### AI 端点（本次不涉及，仅交代基线）

`kDefaultTutorBaseUrl = kDefaultMimoBaseUrl = https://api.xiaomimimo.com/v1`（MiMo 公网 API，key 随 App 预填）。手机直连，无需 PC/局域网/adb reverse。`:3100` 本地网关仅是用户手动切换时的可选路径，`tunnel_keepalive.ps1` 只保活 `tcp:8765` 不保活 `:3100`。
